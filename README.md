# gidvms-tilda-photos

Temporary public image storage for importing product photos into Tilda.

## Гид в мире сантехники — правила фотографий для импорта в Tilda

Зафиксировано по указанию пользователя: 22.09.2026.

### Главный принцип

Пользователь передаёт CSV, XLSX, архив или ссылки на товары. Подготовка фотографий выполняется вместе с подготовкой импорта: получить оригиналы, оптимизировать, разместить в уже используемом хранилище, проверить прямые ссылки и вставить их в CSV. Не перекладывать на пользователя ручную загрузку каждой фотографии.

### Хранилище

GitHub: `Santehsalon-coder/gidvms-tilda-photos`, основная ветка `main`.

Для каждой новой партии использовать отдельную папку, внутри — привязку к идентификаторам товаров. Не заменять, не удалять и не переименовывать ранее опубликованные фотографии без отдельного согласования.

### Порядок работы

1. Прочитать исходную выгрузку. Сопоставить товары, их идентификаторы, фотографии и порядок снимков. Проверить ссылки поставщика или Авито. Уже подготовленные подходящие фотографии использовать повторно, не перезаливать без необходимости.
2. Скачать доступные оригиналы разрешённым способом. Если обычная ссылка Авито не отдаёт картинку, проверить прямой адрес той же фотографии по imageSlug. Ранее, 21.09.2026, успешно использовался `https://00.img.avito.st/image/1/<imageSlug>`. Этот адрес — предыдущий рабочий способ, а не гарантия доступности будущих фотографий: при каждой партии проверять его заново. Для поставщиков также проверять реальные адреса файлов, а не страницы с фотографиями.
3. Оптимизировать без потери качества по умолчанию: сохранять разрешение, пропорции и содержимое изображения; проверять совпадение декодированных пикселей и корректность цветового профиля/ориентации. Выбирать меньший из корректных вариантов: исходник, JPEG с оптимизацией без потерь, WebP без потерь. Не увеличивать вес ради смены формата. Уже компактный исходник допустимо оставить без изменений. Уменьшение разрешения или сжатие с потерями не называть «без потери качества»; при необходимости согласовать отдельно.
4. Не растягивать товар, не дорисовывать, не добавлять белые поля и не обрезать важные детали. Не подменять недоступный снимок похожим товаром. Если исходные пропорции не соответствуют принятому формату 4:3, сообщить об этом, а не менять изображение молча. Противоречивые фото и чертежи вынести на согласование; не исключать их незаметно.
5. Разместить подготовленные публичные товарные фотографии в указанном хранилище. В итоговом CSV по умолчанию использовать проверенные прямые HTTPS-адреса файлов из этого хранилища, закреплённые за коммитом: `https://raw.githubusercontent.com/Santehsalon-coder/gidvms-tilda-photos/<commit>/<path>`. Не вставлять вместо изображения страницу GitHub, временную ссылку на артефакт или адрес файла из рабочего контейнера.
6. Проверить каждую итоговую ссылку: успешный HTTP-ответ, действительное изображение, возможность декодировать файл, соответствие нужному товару, порядок, количество, разрешение и размер. Одного ответа HTTP 200 недостаточно. Не писать «все фото проверены», если проверена только часть.
7. Вставить эти ссылки в поле фотографий CSV. Сохранить идентификаторы товаров и остальные согласованные данные. Перед передачей проверить структуру CSV, разделитель, кодировку и отсутствие лишних строк/дублей. Результат — готовый импорт, без необходимости вручную прикреплять фотографии.

### Крупные выгрузки

Работать партиями с сохранением результата и возможностью продолжить после сбоя. Ограничивать одновременные запросы; не запускать неограниченное скачивание. Не скачивать и не публиковать одинаковый файл повторно без необходимости. Вести отчёт: товар, номер фото, источник, итоговый адрес, исходный/итоговый вес, способ оптимизации, результат проверки и ошибки. Хранить резервную копию. До массового импорта явно сообщать о проблемных товарах и фотографиях.

### Когда источник недоступен

Недоступность изображения по одной ссылке не означает, что оригинал нельзя получить другим разрешённым способом. Проверить ранее применявшийся прямой адрес, разрешённую публичную ссылку поставщика или переданный архив. Не обходить авторизацию и ограничения доступа. Если сам оригинал недоступен, сообщить, какие фотографии не получены, и запросить архив или рабочие ссылки/доступ. Не выдавать неполный комплект за полностью готовый и не обещать, что любая фотография всегда будет доступна.

### Безопасность и завершение

Репозиторий публичный: размещать только разрешённые к публикации товарные изображения. Не публиковать пароли, токены, закрытые подписанные ссылки поставщиков, личные данные покупателей или исходные выгрузки с такими сведениями. Не менять видимость репозитория.

Размещение фотографий и подготовка CSV не означают, что импорт в Tilda уже выполнен: результат загрузки и отображение товаров проверяются отдельно после импорта пользователем.
